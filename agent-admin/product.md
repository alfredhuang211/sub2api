# Agent Admin 产品说明

## 1. 项目定位

`agent-admin` 是 sub2api 主系统下的独立关联项目，用于建设代理经销商管理平台。项目独立开发、独立构建、可独立部署，但账号体系、认证能力和核心业务数据与原系统保持一致。

`agent-admin` 同时支持原系统管理员和代理商登录。管理员用于指定代理、配置代理层级、配置分成比例、调整客户来源关系和查看代理业务数据；代理商用于查看自己的客户、推荐、分成、结算和经营数据。

## 2. 阶段目标

### P0：管理员与代理商基础工作台

- 原系统管理员和已被指定为代理商的用户都可以登录 `agent-admin`。
- 管理员可以从原系统已有用户中指定代理商。
- 管理员可以设置代理等级、上级代理和分成比例。
- 管理员可以把指定客户的来源或推荐关系设置为某个代理商。
- 管理员可以查看代理名下客户、推荐、分成和结算统计。
- 代理商使用原系统同一套账号体系登录。
- 代理商查看自己名下客户、推荐用户、套餐消耗、分成和结算记录。
- 代理商可以把自己通过推荐码引入的推荐用户指定为下级代理商。
- 代理商可以在权限范围内设置下级代理分成比例。

### P1：结算与运营增强

- 代理商可发起结算申请。
- 管理员可审核结算。
- 完善客户详情、订单详情、分成明细和经营报表。

### P2：代理经营能力扩展

- 代理专属套餐和价格策略。
- 代理结算申请。
- 代理员工子账号。
- 客户分层运营和报表导出。
- 自动结算或第三方打款集成。

## 3. 账号体系与登录

账号体系与原系统保持一致：

- 读写同一套用户账号数据库。
- 复用原系统登录方式、认证逻辑、JWT/OAuth 能力。
- 代理身份是原系统用户账号上的业务身份扩展，不新建独立登录账号体系。
- 后续如代理业务需要独立表，应在同一账号体系下扩展代理业务表。

登录规则：

- 原系统管理员可以登录 `agent-admin`。
- 已被指定为代理商的原系统用户可以登录 `agent-admin`。
- 管理员和代理商使用与原系统一致的账号密码。
- 后端需要在认证主体中识别 `admin`、`agent`、`agent_level` 等身份信息。

## 4. 用户角色

### 平台管理员

平台管理员负责管理全局代理体系：

- 指定原系统用户为代理商。
- 设置代理等级。
- 设置 2 级、3 级代理的上级代理。
- 设置代理商分成比例。
- 手动调整客户来源或推荐关系。
- 查看全局代理业务数据。
- 审核结算。
- 管理结算规则和风控规则。

### 代理商

代理商是原系统用户账号上的业务身份。代理商可访问自己权限范围内的数据：

- 查看自己名下客户。
- 查看推荐用户。
- 查看客户套餐消耗。
- 查看分成统计。
- 查看结算记录。
- 管理自己的推广信息。
- 2 级、3 级代理可以查看自己的上级代理账号。
- 指定自己推荐用户为下级代理商。
- 在权限范围内设置下级代理分成比例。

### 普通用户

普通用户是未被指定为代理商的原系统用户。普通用户可以被代理通过推荐码引入，也可以被管理员手动归属到某个代理商名下。

普通用户如果被代理商指定为下级代理商，则从普通用户升级为代理商身份。

### 代理员工

后续可扩展代理员工子账号，用于销售、客服、财务等分工。该能力不进入初期范围。

## 5. 代理层级规则

代理支持 3 级：

- 1 级代理：由管理员直接指定，无需上级代理。
- 2 级代理：必须指定上级代理。
- 3 级代理：必须指定上级代理。

层级约束：

- 一个用户同一时间只能绑定一个代理身份。
- 2 级和 3 级代理必须存在有效上级代理。
- 下级代理的分成比例不能突破上级或平台设定的上限。
- 代理商只能把通过自己推荐码引入的推荐用户指定为自己的下级代理商。
- 管理员不受推荐码来源限制，可以直接指定代理层级和客户归属。

建议补充约束：

- 1 级代理只能由管理员创建。
- 2 级代理可由管理员创建，也可由 1 级代理从自己的推荐用户中指定。
- 3 级代理可由管理员创建，也可由 2 级代理从自己的推荐用户中指定。
- 不建议允许 3 级代理继续发展下级代理，避免超过 3 级链路。

## 6. 客户归属与推荐关系

客户归属来源支持两种方式：

- 自然推荐：用户通过代理推荐码注册或绑定。
- 管理员手动归属：管理员把指定客户的来源或推荐关系设置为某个代理商。

归属规则：

- 两种来源都进入统一的代理客户关系。
- 一个客户同一时间只能归属一个代理。
- 客户归属设置后，该客户应出现在代理商的 `agent-admin` 客户列表中。
- 自然推荐关系继续出现在原系统推荐模块中。
- 管理员手动归属初期只写入 `agent-admin` 代理业务表，不默认出现在原系统推荐模块中。
- 管理员手动调整客户来源或推荐关系时，需要记录审计日志。
- 客户来源调整记录需要保留原代理、新代理、调整原因、操作管理员和操作时间。
- 管理员手动归属客户仅影响未来套餐周期，不影响历史分成，不自动补发历史分成。
- 如果管理员在套餐周期中间手动归属客户，默认从下一个完整套餐周期生效。
- 不允许代理之间自行转移客户归属；后续仅保留管理员调整能力。

原系统推荐模块默认保持不变，`agent-admin` 仅利用原系统已有推荐上下级关系作为客户归属和下级代理创建的依据。代理业务扩展应避免破坏原推荐系统现有逻辑。同时保留后续在原推荐系统中添加兼容记录的能力，但该能力不作为初期默认实现。

## 7. 分成与结算规则

### 分成比例

默认分成比例：

- 1 级代理默认比例：20%。
- 2 级代理默认比例：15%。
- 3 级代理默认比例：10%。

分成比例可以由以下角色调整：

- 平台管理员可以针对 1 级代理额外调整比例。
- 1 级代理可以手工调整给自己下级 2 级代理的比例。
- 2 级代理可以手工调整给自己下级 3 级代理的比例。

限制规则：

- 上级代理只能在自身权限范围内设置下级代理分成比例。
- 下级代理分成比例不能突破上级或平台设定的上限。
- 下级代理设置给更下一级代理的比例，必须低于上级设置给该下级代理的比例。
- 当上级调整比例导致已有下级比例不再合法时，应阻止保存并提示先调整下级比例。
- 分成比例变更需要记录设置人、设置时间和生效时间。
- 分成比例默认从下一套餐周期生效。
- 管理员可以指定未来生效时间。
- 分成比例允许设置为 0%。
- 分成比例精度到两位小数，例如 12.50%。
- 历史分成应按当时生效比例计算，不能被后续比例变更污染。

多级代理采用差额分成：

- 平台设置默认代理分成比例，管理员可额外调整 1 级代理比例。
- 1 级代理在自身比例范围内设置 2 级代理比例。
- 2 级代理在自身比例范围内设置 3 级代理比例。
- 下级代理拿自己的比例。
- 上级代理拿自己比例与直接下级比例之间的差额。
- 这样可以确保整条链路的总分成不超过最高上级代理比例。

示例：

- 客户周期确认收入为 1000。
- 1 级代理比例为 20%。
- 2 级代理比例为 15%。
- 3 级代理比例为 10%。
- 如果客户归属 3 级代理，则 3 级代理拿 1000 × 10% = 100，2 级代理拿 1000 × (15% - 10%) = 50，1 级代理拿 1000 × (20% - 15%) = 50，平台总分成支出为 200。
- 如果客户归属 2 级代理，则 2 级代理拿 1000 × 15% = 150，1 级代理拿 1000 × (20% - 15%) = 50。
- 如果客户归属 1 级代理，则 1 级代理拿 1000 × 20% = 200。

### 分成来源

代理商可获得的分成来自其引入客户的套餐消耗，不是按充值即时结算。

已确认规则：

- 分成按套餐周期到期触发统计。
- 分成由每日定时任务扫描已到期套餐周期后生成。
- 分成金额按周期确认收入计算。
- 周期确认收入以套餐周期结束时的订单实付金额为准。
- 客户在一个套餐周期到期后，系统按对应代理分成比例统计该周期可结算分成。
- 系统在客户当期套餐周期到期后统计代理分成，并进入结算流程。
- 只有周期结束时已经确认、未退款的收入进入分成。
- 退款发生在结算前，则扣减本周期周期确认收入。
- 退款发生在结算后，则生成负数冲正记录，在后续结算中抵扣。
- 负数冲正来源包括结算后退款、订单撤销、支付争议或管理员账务调整等导致已结算分成需要追回的情况。
- 客户月中升级、降级、续费时，按套餐周期结束时对应订单的实付金额确认收入。
- 金额统一以最小货币单位存储和计算，例如分或 cents。
- 展示金额时保留两位小数。
- 差额分成按每级分别计算，尾差归平台。

### 结算流程

建议流程：

1. 客户套餐周期到期。
2. 系统按客户归属代理和代理分成比例生成分成统计。
3. 系统校验最低结算金额、冻结期、风控状态。
4. 系统自动生成待结算记录。
5. 后续可扩展代理提交结算申请。
6. 平台管理员审核，最低结算金额为 100 元。
7. 财务打款或系统自动转账。
8. 生成结算流水。

结算参数：

- 最低结算金额：100 元。
- 分成冻结期：5 天。
- 结算周期：自然月，到月底结算。
- 负数冲正允许结转抵扣后续分成。

结算状态：

- `pending`：待结算。
- `frozen`：冻结中。
- `payable`：可结算。
- `paid`：已结算。
- `reversed`：已冲正。

冲正展示：

- 管理员端展示完整冲正原因、关联订单、关联结算记录和内部备注。
- 代理端展示冲正金额、关联订单、原因分类和发生时间，不展示内部备注。

## 9. 权限边界

基础原则：

- 代理端数据隔离必须在后端服务层强制实现。
- 前端隐藏不能作为权限边界。
- 所有代理体系写操作都需要审计。

管理员权限：

- 可以登录 `agent-admin`。
- 可以指定代理商。
- 可以设置代理等级和上级代理。
- 可以设置代理分成比例。
- 可以手动把指定客户来源或推荐关系设置为代理商。
- 可以查看所有代理数据。

代理商权限：

- 只能访问自己名下客户。
- 2 级、3 级代理可以查看自己的上级代理账号。
- 可以查看下级代理的汇总数据和分成贡献。
- 不能查看下级代理客户邮箱、订单明细等客户明细数据。
- 客户明细仅对直接归属代理和管理员可见。
- 不能访问其他代理数据。
- 不能访问平台全局配置。
- 不能访问上游账号、渠道池、系统日志、风控配置等主后台资源。
- 只能把通过自己推荐码引入的推荐用户指定为下级代理商。

## 10. 技术架构

### 10.1 前端架构

当前项目目录：`agent-admin`

技术栈：

- Vue 3
- TypeScript
- Vite
- Axios
- 原生 CSS

目录规划：

```text
agent-admin/
  src/
    api/          # API 客户端和接口类型
    components/   # 可复用 UI 组件
    views/        # 页面级组件
    main.ts       # 应用入口
    App.vue       # 当前 MVP 工作台
    style.css     # 全局样式
```

开发服务器默认端口为 `3100`，通过 Vite proxy 将 `/api` 转发到 sub2api 后端。

### 10.2 后端 API

短期可复用现有能力：

- `/api/v1/admin/affiliates/users`
- `/api/v1/admin/affiliates/invites`

- `/api/v1/admin/affiliates/transfers`

### 10.3 认证与授权

认证模型：

- 复用主系统登录能力。
- 账号体系与主系统一致。
- 原系统管理员和已被指定为代理商的用户都可以登录 `agent-admin`。
- 管理员和代理商使用与原系统一致的账号密码。
- 管理员在 `agent-admin` 中指定原系统用户为代理商。
- 代理商登录时，服务端根据当前登录用户确认是否具备代理资格。
- JWT 中可增加角色或权限声明，例如 `role=admin`、`role=agent`、`agent_level=1`。
- API 层区分 admin token 和 agent token，但底层账号体系保持一致。

建议权限点：

agent.customers.read
agent.orders.read
agent.commissions.read
agent.settlements.read
agent.settlements.create
agent.profile.update
agent.children.manage
admin.agents.manage
admin.agent_customer_relations.manage
admin.agent_settlements.manage

### 10.4 数据模型建议

建议补充以下代理业务表或等价模型：

- 代理档案：用户 ID、代理名称、联系人、等级、上级代理、状态、结算方式。
- 代理层级关系：代理 ID、上级代理 ID、层级、路径、状态。
- 代理客户关系：代理 ID、客户 ID、绑定来源、推荐码、绑定方式、绑定时间、有效期。
- 客户来源调整记录：客户 ID、原代理、新代理、调整原因、操作管理员、操作时间。管理员调整原因必填。
- 代理分成配置：代理 ID、设置人、分成比例、上限、启用时间、失效时间。
- 周期分成记录：客户 ID、代理 ID、套餐周期、订单实付金额、周期确认收入、分成比例、分成金额、冲正金额、结算状态、冲正原因分类。

- 代理审计日志：操作人、操作对象、操作类型、变更前后内容、操作时间。
- 代理员工：子账号、角色、权限。该模型后续扩展。

## 12. 已确认结论与待讨论问题

### 12.1 已确认结论

- 管理员和代理商都可以登录 `agent-admin`。
- 管理员和代理商使用与原系统一致的账号密码。
- 一个客户同一时间只能归属一个代理。
- 分成按套餐周期到期触发统计。
- 分成金额按周期确认收入计算，周期确认收入以套餐周期结束时的订单实付金额为准。
- 分成由每日定时任务扫描已到期套餐周期后生成。
- 多级代理采用差额分成。
- 管理员手动归属客户仅影响未来套餐周期；周期中调整从下一个完整套餐周期生效。
- 下级代理创建不需要管理员审核，管理员可查看并调整。
- 原系统推荐模块保持不变，`agent-admin` 仅利用原系统推荐上下级关系。
- 保留后续在原系统推荐模块中添加兼容记录的能力，但初期不默认写入。
- 周期结束时已经确认、未退款的收入进入分成；结算前退款扣减本周期，结算后退款生成冲正记录。
- 金额以最小货币单位存储和计算，展示保留两位小数，尾差归平台。
- 分成比例允许 0%，精度到两位小数，例如 12.50%。
- 代理分成比例默认下一套餐周期生效，管理员可指定未来生效时间。
- 下级代理设置给更下一级的比例，必须低于上级设置给该下级代理的比例。
- 上级比例下调导致已有下级比例不合法时，阻止保存并提示先调整下级比例。
- 代理禁用后不可用代理身份登录，不再产生新分成，历史数据保留。
- 禁用某个代理只影响该代理自身；其下级代理身份继续有效，被禁用代理原本应获得的差额分成归平台。
- 不允许代理之间自行转移客户归属。
- 上级代理只能看到下级代理汇总数据和分成贡献，不能查看下级客户明细。
- P0/P1 先做系统生成待结算记录，提现申请后置。
- 最低结算金额 100 元，冻结期 5 天，按自然月到月底结算。
- 负数冲正可结转抵扣后续分成，来源包括结算后退款、订单撤销、支付争议或管理员账务调整。
- 冲正记录管理员端展示完整原因和内部备注；代理端展示金额、关联订单、原因分类和发生时间，不展示内部备注。
- 手动归属客户时管理员调整原因必填。
- 禁用代理名下未重新归属客户，应在管理员页面提示为“无有效代理分成”状态，并支持批量重新归属。
- 上级代理查看下级汇总数据时，P0 只展示自然月汇总。
- 同一用户从普通用户升级为代理后，不回溯过去作为普通客户产生的消费分成，只影响成为代理后的下级和未来周期。
- 结算状态包括 `pending`、`frozen`、`payable`、`paid`、`reversed`。
- 2 级、3 级代理可查看的上级账号字段为用户名、邮箱、代理等级、联系信息；默认不展示手机号。

### 12.3 建议优先讨论的实现细节

#### 原系统推荐模块兼容

已确认初期采用：原推荐系统默认保持不变。自然推荐关系仍由原系统维护，`agent-admin` 读取原推荐上下级关系；管理员手动归属只写入代理业务表，不默认回写原推荐模块。

保留能力：后续可以在原推荐系统中添加兼容记录，使原推荐系统也能展示部分代理归属结果。该能力需要单独设计开关、写入方式和审计逻辑。

#### 代理层级数据可见范围

已确认：上级代理可以看到下级代理的汇总数据和分成贡献，不直接查看下级代理客户明细。客户明细只对直接归属代理和管理员可见。

#### 上级代理禁用影响

已确认：禁用某个代理只影响该代理自身登录和新分成；其下级代理身份继续有效。被禁用代理原本应获得的差额分成归平台，直到管理员调整层级或恢复代理。

#### 分成比例下调后的下级处理

已确认：阻止上级比例下调，并提示先调整下级比例。下级设置给更下一级的比例，也必须低于上级设置给该下级的比例。

#### 结算参数

已确认：

- 最低结算金额：100 元。
- 分成冻结期：5 天。
- 结算周期：自然月，到月底结算。
- 负数冲正：允许结转抵扣后续分成。

负数冲正来源包括结算后退款、订单撤销、支付争议或管理员账务调整等导致已结算分成需要追回的情况。
